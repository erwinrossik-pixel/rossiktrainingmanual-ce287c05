# Project rules

- Training time is written only by the single app-wide `TrainingTimeAutoTracker` (mounted once in `App`, `useTrainingTimer({ autoTrack: true })`), which tracks only on training pages, heartbeats each minute and pauses on tab hide or other pages; other `useTrainingTimer` instances are display-only. Why: multiple writers double-counted or lost time.
- Running `training_time` rows older than the stale window are treated as paused on load. Why: closed tabs/crashes must not count time away as training.
- A chapter that was completed stays completed on later quiz attempts (no downgrade, no lockout); only the admin reset RPC clears it. Why: weak retakes were un-completing passed chapters.
- Unlocking a chapter goes through `unlockChapter` in `useChapterProgress.ts`: insert if missing, otherwise change only rows still `locked`. Why: overwriting reset completed chapters on retakes, while never touching existing rows left learners stuck after an admin reset.
- Admin read access to learner data goes through `can_admin_view_user(owner)`: admins see only users of companies they are approved in; only the master-company super admin sees all companies. Why: platform `admin` role previously exposed other tenants' sessions, certificates and discussions.
- AI edge functions route gateway 402/403/429 through `_shared/aiGatewayError.ts` (status preserved, stable `code`), and batch jobs stop on the first blocking failure; the UI maps the code to a translated message via `src/lib/aiFunctionError.ts`. Why: credit-limit errors surfaced as generic 500s and cron batches kept retrying.
- After sign-in the Auth page always navigates to `/`; the main page decides between training and the pending-approval screen, using the site company's membership or the user's own latest membership. Why: pending and non-site-company users were stuck on the login form.
- Homework ("Teme") answer keys live only in `homework_answer_keys` (trainer-only RLS); learners get scores from the `submit_homework` RPC and correct answers only via `get_homework_solutions` (graded + `show_solutions`), and all grading-field writes go through the homework RPCs, guarded by the `homework_submissions_guard` trigger. Why: learners must never read keys or set their own score.
- Homework UI texts live in `src/lib/homework/i18n.ts` (`useHomeworkT`), separate from `LanguageContext`. Why: keeps the module self-contained and trilingual without growing the global dictionary.
